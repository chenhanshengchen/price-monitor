# 多商品支持实施计划

## 方案概述

**核心思路**: 单文件传递 + 立即导入
- 影刀 JS 提取商品 ID、标题、URL 和 SKU 数据
- Python 写入 `C:\temp\price_<商品ID>.json`
- Python 立即调用 `wsl.exe` 触发 Node.js 导入
- Node.js 按 `platform_product_id` 自动注册/更新商品

**商品身份规则**:
- 唯一标识: `platform_product_id`(从页面 `itemId` 或 URL `id` 参数提取)
- URL 存储: 保留完整 URL,每次导入更新为最新
- 标题存储: `page_title`(自动抓取) + `display_name`(用户编辑)
- 展示优先级: `display_name` → `page_title` → `platform_product_id`

## 步骤 2: 增加商品自动注册/更新方法

### 目标
在 `database.js` 中实现 `findOrCreateProduct(platformProductId, url, pageTitle)` 方法:
- 按 `platform_product_id` 查找商品
- 不存在则注册新商品(品牌从 URL 提取或默认为"未知品牌")
- 已存在则更新 `product_url`、`page_title` 和 `updated_at`
- **不覆盖** `display_name` 和 `price_threshold`

### 修改文件
`src/database.js`

### 正常情况验证
```bash
node -e "
const PriceDatabase = require('./src/database');
(async () => {
  const db = new PriceDatabase();
  await db.init();
  
  // 测试已有商品
  const id1 = db.findOrCreateProduct('563795984293', 'https://new_url', '蔡司新标题');
  console.log('已有商品 ID:', id1); // 应为 1
  
  // 验证未覆盖用户设置
  const product1 = db.db.exec('SELECT display_name, price_threshold, page_title FROM products WHERE id=1')[0].values[0];
  console.log('display_name:', product1[0]); // 应为 null(未被覆盖)
  console.log('price_threshold:', product1[1]); // 应为 10(未被覆盖)
  console.log('page_title:', product1[2]); // 应为 '蔡司新标题'(已更新)
  
  // 测试新商品
  const id2 = db.findOrCreateProduct('999999', 'https://test', '测试商品');
  console.log('新商品 ID:', id2); // 应为 2
  
  db.close();
})();
"
```

### 异常情况处理

| 异常场景 | 处理方式 | 用户反馈 |
|---------|---------|---------|
| platformProductId 为空/null | 抛出错误 | `错误: platform_product_id 不能为空` |
| URL 格式无效 | 记录警告,继续执行 | `警告: URL 格式可能无效: <url>` |
| 品牌提取失败 | 使用默认值"未知品牌" | (静默处理,日志记录) |
| INSERT 违反 UNIQUE 约束 | 查询该商品 ID 并返回 | (静默处理,视为并发插入) |
| 数据库写入失败 | 抛出错误,不静默吞掉 | `错误: 无法创建商品: <具体错误>` |
| page_title 超长(>1000 字符) | 截断为 1000 字符 | `警告: 商品标题过长,已截断` |

### 边界情况

| 边界场景 | 处理方式 |
|---------|---------|
| 同一商品 ID 连续调用两次 | 第二次更新 URL 和 page_title,不创建新记录 |
| 新商品 URL 与已有商品相同 | 允许(URL 不作为唯一性判断) |
| page_title 包含特殊字符/emoji | 正常存储(UTF-8 支持) |
| 提取品牌时 URL 无法解析 | 使用"未知品牌" |

#### 1. 接收并校验 JSON

```python
import json
import pandas as pd
import os
import subprocess
import sys

# 接收 JS 返回的数据
if isinstance(json_str, dict):
    data = json_str
elif isinstance(json_str, str):
    if not json_str or json_str.strip() == "":
        print("错误: json_str 是空字符串", file=sys.stderr)
        sys.exit(1)
    try:
        data = json.loads(json_str)
    except json.JSONDecodeError as e:
        print(f"错误: JSON 格式错误: {e}", file=sys.stderr)
        sys.exit(1)
else:
    print(f"错误: json_str 类型错误: {type(json_str)}", file=sys.stderr)
    sys.exit(1)

# 校验必需字段
if not isinstance(data, dict):
    print("错误: JSON 必须是对象格式", file=sys.stderr)
    sys.exit(1)

item_id = data.get('itemId', '').strip()
if not item_id:
    print("错误: 缺少 itemId 字段", file=sys.stderr)
    sys.exit(1)

skus = data.get('skus', [])
if not skus or not isinstance(skus, list):
    print("错误: 缺少 skus 字段或为空", file=sys.stderr)
    sys.exit(1)

title = data.get('title', '')
url = data.get('url', '')
```

```javascript
// src/api.js
router.patch('/products/:id', (req, res) => {
  const productId = parseInt(req.params.id);
  const { platform_product_id, price_threshold, display_name } = req.body;
  
  try {
    // 校验参数
    if (display_name !== undefined) {
      if (typeof display_name !== 'string') {
        return res.status(400).json({ error: '简称必须是字符串' });
      }
      if (display_name.length > 100) {
        return res.status(400).json({ error: '简称不能超过 100 字符' });
      }
    }
    
    // 构建 UPDATE 语句
    const updates = [];
    const values = [];
    
    if (platform_product_id !== undefined) {
      updates.push('platform_product_id = ?');
      values.push(platform_product_id);
    }
    
    if (price_threshold !== undefined) {
      const threshold = parseFloat(price_threshold);
      if (isNaN(threshold) || threshold < 0) {
        return res.status(400).json({ error: '阈值必须是非负数' });
      }
      updates.push('price_threshold = ?');
      values.push(threshold);
    }
    
    if (display_name !== undefined) {
      updates.push('display_name = ?');
      values.push(display_name || null); // 空字符串转为 null
    }
    
    if (updates.length === 0) {
      return res.status(400).json({ error: '未提供任何更新字段' });
    }
    
    updates.push('updated_at = CURRENT_TIMESTAMP');
    values.push(productId);
    
    const sql = `UPDATE products SET ${updates.join(', ')} WHERE id = ?`;
    db.db.run(sql, values);
    
    res.json({ success: true });
    
  } catch (error) {
    console.error('更新商品设置失败:', error);
    res.status(500).json({ error: error.message });
  }
});
```

## 关键设计决策

### 1. 商品身份唯一性
- **决策**: 使用 `platform_product_id` 作为唯一标识,不使用 `product_url`
- **原因**: URL 包含跟踪参数,同一商品的不同访问会生成不同 URL
- **影响**: 数据库 `platform_product_id` 字段无 UNIQUE 约束(历史原因),通过代码保证唯一性

### 2. 标题存储分离
- **决策**: `page_title`(自动抓取) 和 `display_name`(用户编辑) 分开存储
- **原因**: 用户编辑的简称不应被自动抓取覆盖
- **影响**: 展示逻辑需要判断优先级

### 3. 文件命名不含时间戳
- **决策**: 使用 `price_<商品ID>.json` 而非 `price_<商品ID>_<时间戳>.json`
- **原因**: 每个商品抓完立即导入,不需要保留历史文件
- **影响**: 同一商品连续抓取会覆盖旧文件(但数据库已保存)

### 4. 立即导入而非批量导入
- **决策**: Python 写完文件后立刻调用 WSL 导入
- **原因**: 用户要求"立即触发导入"
- **影响**: 影刀循环抓取多商品时,Node.js 可能并发运行(SQLite 锁机制保证安全)

### 5. 事务回滚策略
- **决策**: 整个导入流程(注册商品 + 创建批次 + 写入 SKU)在一个事务中
- **原因**: 保证数据一致性,失败时完全回滚
- **影响**: 导入失败不会留下半成品数据
