# 正确的数据模型重构方案

**制定时间**: 2026-10-31  
**基于**: 用户审阅反馈和专业建议  
**原则**: 商品—SKU—采集批次—价格记录 四层结构

---

## 一、为什么不采用方案 A

### 原报告的错误

| 错误 | 实际后果 | 纠正 |
|------|---------|------|
| 对 `product_url` 建唯一索引 | 同一商品的多个 SKU 使用相同链接，违反唯一约束 | 商品表独立，SKU 关联商品 |
| 继续使用 `UNIQUE(package_name, refraction)` | 不同商品的同名套餐会冲突 | 改为 `UNIQUE(product_id, package_name, refraction)` |
| 批次没有关联商品 | 多商品时无法确定数据归属 | 批次表增加 `product_id` |
| 导入成功 = 采集完整 | JSON 可能只有部分 SKU | 分开记录 status 和 completeness |
| 示例 SQL 缺 `record_time` | 按表结构会插入失败 | 修正示例，使用批次关联 |
| 旧批次标记为成功 | 无依据伪造状态 | 标记为 "unknown" |
| 认为 REAL 类型价格保真 | 浮点数有精度问题 | 使用 TEXT 存储或十进制运算 |
| 假设时区为北京时间 | 未检查代码就断言 | 检查实际生成代码 |

### 为什么当前适合重构

- ✅ 数据量小（287 条，83 个 SKU）
- ✅ 只有一个商品，迁移简单
- ✅ 趁早纠正，避免将来更大成本
- ✅ 前端还未开发，不存在兼容负担

## 二、正确的数据结构

### 1. 商品表 `products`

**职责**：一条记录代表一个商品页面

```sql
CREATE TABLE products (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  product_url TEXT NOT NULL UNIQUE,           -- 你手动填写，唯一
  platform_product_id TEXT NOT NULL,          -- 平台商品 ID（如天猫 ID）
  brand TEXT NOT NULL,
  display_name TEXT,                          -- 可选，页面显示名称
  price_threshold REAL NOT NULL DEFAULT 5.0 CHECK(price_threshold >= 0),
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_products_brand ON products(brand);
```

**说明**：
- `id` - 系统内部 ID，用于关联
- `platform_product_id` - 你提供的平台商品 ID（如 "563795984293"）
- `product_url` - 商品链接，唯一性字段
- `price_threshold` - 每个商品独立的阈值

**重要**：
- 商品信息由你手动维护，不从抓取结果自动生成
- 不擅自改写、裁剪你填写的链接
- 不与 SKU JSON 中的字段混淆

---

### 2. SKU 表 `skus`

**职责**：一条记录代表一个商品下的一个 SKU

```sql
CREATE TABLE skus (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  product_id INTEGER NOT NULL,
  package_name TEXT NOT NULL,
  refraction TEXT NOT NULL DEFAULT '',        -- 允许空字符串
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(product_id, package_name, refraction),
  FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE
);

CREATE INDEX idx_skus_product ON skus(product_id);
```

**说明**：
- `product_id` - 关联到 products 表
- 唯一约束：同一商品内，package_name + refraction 唯一
- 不同商品可以有同名套餐

**空值规则**：
- 统一使用空字符串 `''` 表示无折射率
- 避免 NULL 和空字符串混用导致重复

---

### 3. 采集批次表 `collection_batches`

**职责**：记录每次数据采集和导入的批次信息

```sql
CREATE TABLE collection_batches (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  product_id INTEGER NOT NULL,
  imported_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  collected_at DATETIME,                      -- 抓取时间（未知时为 NULL）
  status TEXT NOT NULL DEFAULT 'importing' CHECK(status IN ('importing', 'success', 'failed')),
  completeness TEXT NOT NULL DEFAULT 'unknown' CHECK(completeness IN ('unknown', 'complete', 'partial')),
  source_record_count INTEGER,                -- JSON 中的记录数
  inserted_record_count INTEGER,              -- 实际插入的记录数
  error_message TEXT,
  FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE
);

CREATE INDEX idx_batches_product ON collection_batches(product_id);
CREATE INDEX idx_batches_imported_at ON collection_batches(imported_at);
```

**status 说明**：
- `importing` - 正在导入中
- `success` - 导入成功（读入了 JSON 数据）
- `failed` - 导入失败

**completeness 说明**：
- `unknown` - 不确定是否完整（历史数据、无对比依据）
- `complete` - 确认完整（所有预期 SKU 都存在）
- `partial` - 部分数据（缺少部分 SKU）

**重要区分**：
- 导入成功 ≠ 采集完整
- 成功读入 68 条，只能证明导入了 68 条，不代表抓到了全部 SKU

---

### 4. 价格记录表 `price_snapshots`

**职责**：记录每个批次中每个 SKU 的价格快照

```sql
CREATE TABLE price_snapshots (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  batch_id INTEGER NOT NULL,
  sku_id INTEGER NOT NULL,
  daily_price TEXT NOT NULL,                  -- 使用 TEXT 保留原始价格
  promo_price TEXT,                           -- NULL 表示无活动价
  UNIQUE(batch_id, sku_id),
  FOREIGN KEY (batch_id) REFERENCES collection_batches(id) ON DELETE CASCADE,
  FOREIGN KEY (sku_id) REFERENCES skus(id) ON DELETE CASCADE
);

CREATE INDEX idx_snapshots_batch ON price_snapshots(batch_id);
CREATE INDEX idx_snapshots_sku ON price_snapshots(sku_id);
```

**价格存储**：
- 使用 TEXT 类型保留原始字符串（如 "247.35"）
- 避免 REAL 浮点数的精度问题
- 比较时转为 Decimal 或使用十进制运算

**空活动价**：
- NULL 表示无活动价
- 不使用空字符串或 0

## 三、与旧结构的对比

| 旧结构 | 新结构 | 变化 |
|--------|--------|------|
| `products` (实际是 SKU) | `skus` | 表名纠正 |
| 无商品表 | `products` | 新增 |
| 无批次表 | `collection_batches` | 新增 |
| `price_history_v2` | `price_snapshots` | 重命名，关联批次 |
| `product_id` (指向 SKU) | `sku_id` | 字段名纠正 |
| `import_id` (未使用) | `batch_id` | 真正使用 |
| `record_time` (批次标识) | `imported_at` (在批次表) | 语义分离 |

   ```sql
     old_id INTEGER,
     new_id INTEGER
   );
   
   -- 迁移 SKU
   INSERT INTO skus (product_id, package_name, refraction)
   SELECT 1, package_name, COALESCE(refraction, '')
   FROM products AS old_products;
   
   -- 记录映射关系
   INSERT INTO old_to_new_sku
   SELECT old_products.id, skus.id
   FROM products AS old_products
   JOIN skus ON skus.package_name = old_products.package_name
            AND skus.refraction = COALESCE(old_products.refraction, '');
   ```

   ```sql
   -- 按 record_time 分组创建批次

   SELECT 
     1,                         -- product_id
     record_time,               -- imported_at
     NULL,                      -- collected_at（未知）
     'success',                 -- status（能导入说明成功）
     'unknown',                 -- completeness（无法确定）
     COUNT(*)                   -- source_record_count
   FROM price_history_v2
   GROUP BY record_time;
   ```

6. 迁移价格记录
   ```sql
   INSERT INTO price_snapshots (batch_id, sku_id, daily_price, promo_price)
   SELECT 
     cb.id,                                    -- batch_id
     mapping.new_id,                           -- sku_id
     CAST(ph.daily_price AS TEXT),            -- daily_price
     CASE 
       WHEN ph.promo_price IS NULL THEN NULL
       ELSE CAST(ph.promo_price AS TEXT)
     END                                       -- promo_price
   FROM price_history_v2 ph
   JOIN old_to_new_sku mapping ON ph.product_id = mapping.old_id
   JOIN collection_batches cb ON cb.imported_at = ph.record_time;
   ```

- ✅ SKU 与价格记录关联无遗漏

- ✅ 同一商品内重复 SKU 被唯一约束阻止
- ✅ 迁移脚本可重复运行（幂等性）
- ✅ 批次的 completeness 为 'unknown'，不伪造成功状态

### 第 4 步：改造批次导入和价格比较

**工作内容**：

1. 批次 ID 独立生成
   ```javascript
   // 不再用 record_time 作为批次标识
   // 使用数据库自增 ID
   const batchId = await db.createBatch(productId);
   ```

2. 批次归属商品
   ```sql
   INSERT INTO collection_batches (product_id, imported_at)
   VALUES (?, CURRENT_TIMESTAMP);
   ```

3. 使用事务保证原子性
   ```javascript
   async function importBatch(productId, data) {
     return await db.transaction(async (tx) => {
       const batchId = await tx.createBatch(productId);
       
       for (const item of data) {
         const sku = await tx.getOrCreateSKU(productId, item.镜片套餐, item.折射率);
         await tx.insertPrice(batchId, sku.id, item.日常价, item.活动价);
       }
       
       await tx.completeBatch(batchId, 'success', data.length);
       return batchId;
     });
   }
   ```

4. 失败时回滚
   ```javascript
   try {
     await importBatch(productId, data);
   } catch (error) {
     // 事务自动回滚，批次和价格记录都不会保留
     await db.markBatchFailed(batchId, error.message);
   }
   ```

5. 价格比较逻辑
   ```javascript
   async function compareLatestBatches(productId) {
     // 1. 获取当前批次
     const currentBatch = await db.getLatestBatch(productId, { completeness: ['complete', 'unknown'] });
     
     // 2. 获取上一批次
     const previousBatch = await db.getPreviousBatch(productId, currentBatch.id);
     
     if (!previousBatch) {
       return { status: 'no_comparison', message: '暂无可比数据' };
     }
     
     // 3. 只比较两次都存在且活动价有效的 SKU
     const comparison = await db.query(`
       SELECT 
         s.id,
         s.package_name,
         s.refraction,
         curr.promo_price AS current_promo,
         prev.promo_price AS previous_promo
       FROM skus s
       INNER JOIN price_snapshots curr ON curr.sku_id = s.id AND curr.batch_id = ?
       INNER JOIN price_snapshots prev ON prev.sku_id = s.id AND prev.batch_id = ?
       WHERE curr.promo_price IS NOT NULL AND prev.promo_price IS NOT NULL
     `, [currentBatch.id, previousBatch.id]);
     
     // 4. 计算变化（使用十进制运算）
     const changes = comparison.map(row => {
       const currentPrice = parseFloat(row.current_promo);
       const previousPrice = parseFloat(row.previous_promo);
       const changeAmount = currentPrice - previousPrice;
       const threshold = currentBatch.product.price_threshold;
       
       return {
         sku_id: row.id,
         package_name: row.package_name,
         refraction: row.refraction,
         current_promo: row.current_promo,
         previous_promo: row.previous_promo,
         change_amount: changeAmount.toFixed(2),
         exceeds_threshold: Math.abs(changeAmount) > threshold,
         change_type: changeAmount > threshold ? 'increased' 
                    : changeAmount < -threshold ? 'decreased' 
                    : 'unchanged'
       };
     });
     
     return { currentBatch, previousBatch, changes };
   }
   ```

6. SKU 缺失的正确处理
   ```javascript
   // 某 SKU 未出现在本次数据中，不代表活动价取消
   // 只有 SKU 明确出现且活动价为 NULL，才标记为"无活动价"
   
   const skuInCurrent = await db.query(`
     SELECT sku_id FROM price_snapshots WHERE batch_id = ?
   `, [currentBatchId]);
   
   const skuInPrevious = await db.query(`
     SELECT sku_id FROM price_snapshots WHERE batch_id = ?
   `, [previousBatchId]);
   
   const onlyInPrevious = skuInPrevious.filter(id => !skuInCurrent.includes(id));
   
   // 对于 onlyInPrevious 的 SKU，标记为"本次批次缺失"，而非"活动价取消"
   ```

**验收标准**：
- ✅ 连续两次导入生成不同批次（即使在同一秒内）
- ✅ 导入中途故障不会留下半批价格记录
- ✅ 商品 A 的比较不会取到商品 B 的上次价格
- ✅ 测试涨价、降价、未变、活动价为空和 SKU 缺失
- ✅ 所有活动价为空时，显示"暂无可比较活动价"
- ✅ 某 SKU 本次缺失，不误判为"活动价取消"

### 第 5 步：实现每个商品独立的价格阈值

**工作内容**：

1. 商品表已有 `price_threshold` 字段

2. 初始化现有商品阈值
   ```sql
   UPDATE products 
   SET price_threshold = 5.0 
   WHERE price_threshold IS NULL OR price_threshold = 0;
   ```

3. 提供阈值更新 API
   ```javascript
   // PATCH /api/products/:id/settings
   async function updateProductSettings(productId, settings) {
     const { price_threshold } = settings;
     
     // 验证
     if (price_threshold === undefined) {
       throw new Error('缺少 price_threshold 参数');
     }
     
     if (typeof price_threshold !== 'number' || price_threshold < 0 || !isFinite(price_threshold)) {
       throw new Error('price_threshold 必须是非负有限数字');
     }
     
     // 更新
     await db.query(`
       UPDATE products 
       SET price_threshold = ?, updated_at = CURRENT_TIMESTAMP 
       WHERE id = ?
     `, [price_threshold, productId]);
     
     return { success: true };
   }
   ```

4. 比较时使用当前商品阈值

   ```javascript
   const exceedsThreshold = Math.abs(changeAmount) > threshold;
   ```

## 六、关键验证点（四个归属）

**每个归属必须通过验证**：

1. **导入归属商品**
   - ✅ 商品 A 的 JSON 不会导入到商品 B

2. **批次归属商品**
   - ✅ 查询商品 A 的批次，不会返回商品 B 的批次

3. **比较归属商品**
   - ✅ 商品 A 的比较，不会取到商品 B 的上次价格

4. **阈值归属商品**
   - ✅ 修改商品 A 的阈值，不影响商品 B

**验证脚本**：
```javascript
// test/归属验证.js
async function testOwnership() {
  // 1. 创建两个测试商品
  const productA = await createProduct('A');
  const productB = await createProduct('B');
  
  // 2. 分别导入数据
  await importData(productA.id, testDataA);
  await importData(productB.id, testDataB);
  
  // 3. 验证批次归属
  const batchesA = await getBatches(productA.id);
  const batchesB = await getBatches(productB.id);
  assert(batchesA.every(b => b.product_id === productA.id));
  assert(batchesB.every(b => b.product_id === productB.id));
  
  // 4. 验证比较归属
  const comparisonA = await getComparison(productA.id);
  assert(comparisonA.previous_batch.product_id === productA.id);
  
  // 5. 验证阈值归属
  await updateThreshold(productA.id, 10.0);
  const updatedA = await getProduct(productA.id);
  const unchangedB = await getProduct(productB.id);
  assert(updatedA.price_threshold === 10.0);
  assert(unchangedB.price_threshold !== 10.0);
  
  console.log('✅ 四个归属验证通过');
}
```

## 七、总结

### 核心原则

1. **正确的四层结构**
   - 商品 → SKU → 批次 → 价格记录

2. **明确的归属关系**
   - 每个批次归属一个商品
   - 每次比较在同一商品内
   - 每个阈值属于一个商品

3. **完整性与成功分离**
   - 导入成功 ≠ 采集完整
   - 旧数据标记为 "unknown"

4. **SKU 缺失的正确理解**
   - 本次未出现 ≠ 活动价取消
   - 只有明确出现且为 NULL 才是"无活动价"

5. **价格精度**
   - 使用 TEXT 存储原始价格
   - 比较时使用十进制运算
