## 🎯 关键改动点

### 1. 数据库路径切换
- 旧：`./data/price_monitor.db`
- 新：`./data/price_monitor_new.db`

### 2. 表结构变化

**旧表结构**：
- `price_history` (package_name, refraction, daily_price, promo_price, record_time)

**新表结构**：
- `products` (商品表) - 已有 1 条记录
- `skus` (SKU 表) - 已有 83 条记录
- `collection_batches` (批次表) - 新数据会创建新批次
- `price_snapshots` (价格快照表) - 存储价格

### 3. 业务逻辑变化

**旧逻辑**：
```
读取 JSON → 查找最新价格 → 比较 → 插入新记录
```

**新逻辑**：
```
读取 JSON → 创建批次 → 查找/创建 SKU → 插入价格快照 → 比较最近 2 个批次
```

### 步骤 7.3：重写 src/database.js

**核心改动**：

1. **固定商品 ID = 1**（当前只监控蔡司）

2. **新增方法**：
   - `createBatch(productId)` - 创建新批次
   - `findOrCreateSKU(productId, packageName, refraction)` - 查找或创建 SKU
   - `insertPriceSnapshot(batchId, skuId, dailyPrice, promoPrice)` - 插入价格快照
   - `getLatestTwoBatches(productId)` - 获取最近 2 个批次
   - `getPriceChanges(productId, currentBatchId, previousBatchId)` - 比较批次价格

3. **删除方法**：
   - 旧的 `getLatestPrice()` - 不再需要
   - 旧的 `insertPrice()` - 被 `insertPriceSnapshot()` 替代

4. **价格格式**：
   - REAL → TEXT
   - `parseFloat("247.35")` → `"247.35"` (字符串)

5. **外键约束**：
   - 开启：`PRAGMA foreign_keys = ON`

### 步骤 7.4：修改 src/priceMonitor.js

**核心改动**：

1. **processData() 重写**：
```javascript
// 旧逻辑：逐条查询、比较、插入
for (const item of data) {
  const latest = this.db.getLatestPrice(...);
  if (latest) { /* 比较 */ }
  this.db.insertPrice(...);
}

// 新逻辑：批次导入
const batchId = this.db.createBatch(1);
for (const item of data) {
  const skuId = this.db.findOrCreateSKU(1, packageName, refraction);
  this.db.insertPriceSnapshot(batchId, skuId, dailyPrice, promoPrice);
}
const changes = this.db.getPriceChanges(1, batchId, previousBatchId);
```

2. **价格处理**：
```javascript
// 旧：parseFloat(priceStr)
// 新：priceStr 直接作为 TEXT（或转为标准格式）

// 如果是 "¥247.35" → "247.35"
// 如果是 "未知" → null
```

3. **活动价 NULL 处理**：
```javascript
// 空字符串 '' → null
// '未知' → null
```

## ⚠️ 潜在问题和安全检查

### 问题 1：SKU 找不到（新 SKU）
**现象**：JSON 里有新的 package_name + refraction 组合  
**处理**：`findOrCreateSKU()` 会自动创建新 SKU

### 问题 2：价格格式不一致
**现象**：JSON 里的价格是 "¥247.35" 或 "247.35元"  
**处理**：`parsePrice()` 统一提取数字部分

### 问题 3：活动价为 "0" 或 "0元"
**现象**：可能被误认为有活动价  
**处理**：0 元活动价视为无活动价（转为 NULL）

### 问题 4：批次创建失败
**现象**：事务未提交或数据库写入失败  
**处理**：每次导入后调用 `save()` 确保持久化
