- Node.js 导入时，所有 SKU 使用相同的 `record_time`（数据库插入时间）

**批次完整性判断**：
- ✅ 有日志记录"执行完成"
- ❌ 日志没有与数据库记录关联

## 二、数据库现状分析

### 当前表结构

#### products 表（实际是 SKU 表）
```sql
CREATE TABLE products (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  package_name TEXT NOT NULL,           -- SKU 套餐名称
  refraction TEXT NOT NULL,             -- SKU 折射率
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  status TEXT DEFAULT 'active',
  CONSTRAINT unique_product UNIQUE(package_name, refraction)
)
```

**问题**：
- ❌ 表名叫 `products` 但实际存储的是 **SKU**
- ❌ 缺少商品维度（product_url, product_id, brand）
- ❌ 一个商品有多个 SKU，但没有商品-SKU 关联

#### price_history_v2 表
```sql
CREATE TABLE price_history_v2 (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  product_id INTEGER NOT NULL,          -- 外键到 products（实际是 SKU ID）
  daily_price REAL NOT NULL,
  promo_price REAL,                     -- NULL 表示无活动价 ✅
  record_time DATETIME NOT NULL,
  import_id INTEGER,                    -- 批次ID（都是 NULL）
  CONSTRAINT unique_record UNIQUE(product_id, record_time),
  FOREIGN KEY (product_id) REFERENCES products(id)
)
```

**问题**：
- ❌ `product_id` 字段名误导（实际是 sku_id）
- ❌ `import_id` 存在但从未使用（都是 NULL）
- ✅ `promo_price` 正确使用 NULL 表示无活动价
- ✅ 价格保留原始小数，不四舍五入

#### data_imports 表（已设计但未创建）
```sql

CREATE TABLE data_imports (

  source TEXT NOT NULL DEFAULT 'yingdao_rpa',
  record_count INTEGER,
```

**状态**：❌ 表未创建，无法追踪批次状态

## 五、重构方案

### 方案对比

#### 方案 A：最小改动方案（推荐）

**原则**：沿用现有结构，补充缺失字段，保持单商品模式

**改动**：
1. 在 `products` 表增加商品元信息字段
2. 激活 `data_imports` 表追踪批次
3. 修改导入逻辑生成 `import_id`

**优点**：
- ✅ 改动最小，风险低
- ✅ 不需要大规模数据迁移
- ✅ 保持现有代码大部分可用

**缺点**：
- ❌ 表名语义仍然混乱（products 实际是 SKU）
- ❌ 多商品扩展时需再次重构

---

#### 方案 B：正确建模方案

**原则**：重构为商品-SKU 两层结构

**改动**：
1. 新建 `products` 表（真正的商品表）
2. 重命名现有 `products` 为 `skus`
3. `price_history_v2` 的 `product_id` 改为 `sku_id`
4. 迁移所有数据

**优点**：
- ✅ 数据模型清晰正确
- ✅ 多商品扩展无障碍
- ✅ 表名与实际一致

**缺点**：
- ❌ 改动巨大，风险高
- ❌ 需要全量数据迁移
- ❌ 现有代码大量修改

---

### 推荐方案：方案 A（最小改动）

**理由**：
1. 当前只监控一个商品，多商品是未来需求
2. 需要快速上线前端页面

### 步骤 2：激活批次追踪

**目标**：记录每次采集的批次状态

**创建 data_imports 表**：
```sql
CREATE TABLE IF NOT EXISTS data_imports (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  import_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  source TEXT NOT NULL DEFAULT 'yingdao_rpa',
  record_count INTEGER,
  status TEXT CHECK(status IN ('success', 'partial', 'failed')),
  error_message TEXT,
  started_at DATETIME,
  completed_at DATETIME
);
```

**修改导入逻辑** (`src/priceMonitor.js`)：
```javascript
async run() {
  const importId = await this.db.createImport(); // 创建批次记录
  
  try {
    const data = this.readJSON();
    const changes = this.processData(data, importId); // 传入 importId
    
    await this.db.completeImport(importId, 'success', data.length);
    return changes;
  } catch (error) {
    await this.db.completeImport(importId, 'failed', 0, error.message);
    throw error;
  }
}
```

**优点**：
- ✅ 可以判断批次是否完整
- ✅ 可以关联日志与数据库
- ✅ 可以显示采集状态
