# 命名约定

本文件记录项目中所有字段、变量、API 参数的一致命名规范。
**任何新增代码必须遵循此约定。如需修改约定，先更新此文件。**

---

## 一、命名规则总则

| 层级 | 规则 | 示例 |
|------|------|------|
| 数据库字段 | snake_case | `platform_product_id` |
| API JSON 字段 | camelCase | `platformProductId` |
| JavaScript 变量 | camelCase | `platformProductId` |
| HTML id 属性 | kebab-case | `changes-count` |
| CSS class | Tailwind 工具类 | `bg-apple-gray-800` |

---

## 二、实体字段名对照表

### 2.1 商品（Product）

| 语义 | 数据库字段 | API JSON | JS 变量 | HTML id |
|------|-----------|---------|---------|---------|
| 系统内部 ID | `products.id` | `id` | `productId` | — |
| 商品链接 | `product_url` | `productUrl` | `productUrl` | — |
| 平台商品 ID（用户填写）| `platform_product_id` | `platformProductId` | `platformId` | — |
| 品牌 | `brand` | `brand` | `brand` | — |
| 显示名称 | `display_name` | `displayName` | `displayName` | — |
| 价格阈值 | `price_threshold` | `priceThreshold` | `threshold` | — |
| 创建时间 | `created_at` | `createdAt` | `createdAt` | — |
| 更新时间 | `updated_at` | `updatedAt` | `updatedAt` | — |

**注意**：
- `id` 是系统生成的自增整数，仅用于内部关联。
- `platform_product_id` 是用户手动填写的平台 ID（如天猫商品 ID），用于展示和识别，不参与数据库关联。
- 不得将两者混用，也不得在 URL 路由中把平台 ID 当系统 ID 传递。

### 2.4 价格快照（PriceSnapshot）

| 语义 | 数据库字段 | API JSON | JS 变量 | HTML id |
|------|-----------|---------|---------|---------|
| 系统内部 ID | `price_snapshots.id` | `id` | `snapshotId` | — |
| 所属批次 | `batch_id` | `batchId` | `batchId` | — |
| 所属 SKU | `sku_id` | `skuId` | `skuId` | — |
| 日常价 | `daily_price` | `dailyPrice` | `dailyPrice` | — |
| 活动价 | `promo_price` | `promoPrice` | `promoPrice` | — |

**注意**：
- `daily_price` 和 `promo_price` 在数据库中均为 TEXT，保留原始字符串精度。
- `promo_price` 为 NULL 表示无活动价，**不得存储空字符串或 `'0'`**。
- 计算价格差时需通过 `parseFloat()` 转换，并在比较前校验是否为有效数字。
- 前端展示时，NULL 活动价显示为 `'-'`，不显示 `'0'` 或 `'¥0'`。

## 三、API 接口字段约定

### 3.1 错误响应格式

所有 API 错误统一格式：

```json
{
  "error": "ERROR_CODE",
  "message": "人类可读的错误描述"
}
```

| 错误码 | HTTP 状态码 | 含义 |
|--------|------------|------|
| `INVALID_PRODUCT_ID` | 400 | 商品 ID 非正整数 |
| `INVALID_PARAMS` | 400 | 其他参数格式错误 |
| `INVALID_THRESHOLD` | 400 | 阈值格式或范围错误 |
| `INVALID_PLATFORM_ID` | 400 | 商品 ID 字段格式错误 |
| `NO_FIELDS` | 400 | PATCH 请求未传任何字段 |
| `PRODUCT_NOT_FOUND` | 404 | 商品不存在 |
| `BATCH_NOT_FOUND` | 404 | 批次不存在 |
| `PREVIOUS_BATCH_NOT_FOUND` | 404 | 上一批次不存在 |
| `BATCH_NOT_BELONG_TO_PRODUCT` | 400 | 批次不属于该商品 |
| `NO_BATCH` | 400 | 该商品无任何批次 |
| `NO_PREVIOUS_BATCH` | 400 | 该商品无可比较的上一批次 |
| `DATABASE_UNAVAILABLE` | 503 | 数据库不可用 |
| `REQUEST_TIMEOUT` | 503 | 请求超时 |
| `SAVE_FAILED` | 500 | 写磁盘失败 |
| `QUERY_FAILED` | 500 | 查询执行异常 |

### 3.2 SKU 价格变动类型

`comparison` 接口返回的 `changeType` 取值：

| 值 | 含义 |
|----|------|
| `'increased'` | 活动价涨幅超阈值 |
| `'decreased'` | 活动价降幅超阈值 |
| `'new_promo'` | 新增活动价（上次 NULL → 本次有值）|
| `'promo_canceled'` | 取消活动价（上次有值 → 本次 NULL）|
| `'unchanged'` | 有活动价但变动未超阈值 |
| `'no_promo'` | 两次均无活动价 |

## 五、时间格式约定

| 场景 | 格式 | 示例 |
|------|------|------|
| 数据库存储 | `YYYY-MM-DD HH:MM:SS`（北京时间，无时区后缀）| `2026-11-02 13:14:29` |
| 前端展示 | 相对时间或 `MM-DD HH:MM` | `刚刚` / `3 小时前` / `10-25 05:31` |
| 日志文件 | ISO 8601 UTC（带 Z 后缀）| `2026-11-02T05:14:29.000Z` |

**注意**：数据库中 `imported_at` 存储的是北京时间（UTC+8），无时区标识。读取时直接作为北京时间展示，不进行时区转换。

## 六、价格比较逻辑约定

- 阈值比较使用**严格大于**（`> threshold`），等于阈值不算超阈值。
- 价格差计算：`currentPromo - previousPromo`，正值为涨价，负值为降价。
- 浮点运算结果展示保留 2 位小数：`(curr - prev).toFixed(2)`。
- 比较前必须用 `parsePrice()` 校验，无效字符串（如损坏数据）应跳过该 SKU，不报错崩溃。
- NULL 活动价不当作 `0` 计算。

---

## 七、数据保留约定

- 保留最近 3 天（当天 + 前两个自然日，按 Asia/Shanghai 划分）。
- 删除操作必须先预览、再备份、最后执行（三步分离）。
- SKU 和商品信息永久保留，只清理批次和价格快照。
